1. EXECUTIVE SUMMARY (WHAT IS ZENIX IN SIMPLE ENGLISH?)
================================================================================
Zenix is an "Antigravity Software Supply Chain and Vulnerability Triage Platform".

Here is what the project does in simple, plain English:
1. Every modern software project relies on hundreds of external open-source 
   packages (like log4j, requests, lodash, or spring). A list of these packages 
   is called an SBOM (Software Bill of Materials).
2. Standard security scanners take this list and report hundreds of CVE 
   vulnerabilities. Most of these reports are "false alarms" because the software 
   never actually calls, imports, or runs the vulnerable function.
3. Zenix solves this problem through an intelligent 5-way correlation engine:
   * Known Vulnerability Check: Queries live Google OSV.dev and official NIST NVD APIs.
   * Active Exploit Likelihood: Checks FIRST.org EPSS exploit probability scores.
   * Zero-Day Catalog: Cross-references the US Government CISA KEV catalog.
   * Global Threat Intelligence: Queries live Shodan for exposed vulnerable servers 
     worldwide and live VirusTotal for multi-engine antivirus malware detections.
   * Real Operating System Memory Introspection (Reachability Analysis): Checks whether 
     the vulnerable library is actually loaded into your laptop's physical RAM memory 
     using Windows Event Tracing (ETW) and live process inspection.
4. If a vulnerability is NOT loaded in memory, Zenix automatically downgrades its 
   risk score by 95% and issues a cryptographically signed VEX document 
   (Vulnerability Exploitability eXchange) with a downloadable forensic PDF report.

[REAL COMPONENT 1] MULTI-FORMAT UNIVERSAL SBOM PARSER
- File Location: backend/pipeline/sbom_parser.py
- What It Does:
  Accepts uploaded SBOM files up to 10 MB. It parses:
  * CycloneDX JSON (all versions from 1.0 up to 1.7+)
  * CycloneDX XML (hardened with defusedxml to prevent XML entity expansion attacks)
  * SPDX JSON & SPDX Tag/Value / Text (.spdx, .txt)
  * SPDX XML
  * NPM package-lock.json and generic requirements manifests
- How It Works:
  Extracts component names, versions, Package URLs (purl), ecosystems, 
  and cryptographic file hashes (SHA-256). An automatic normalization layer 
  unwraps nested root wrappers (e.g. {"sbom": {...}}) without manual configuration.

- How It Works:

  attack vectors, and official vulnerability descriptions.

[REAL COMPONENT 3] LIVE FIRST.ORG EPSS SCORING & CISA KEV FEED
- File Location: backend/pipeline/enricher.py & backend/api/jobs.py
- What It Does:

[REAL COMPONENT 5] AUDITABLE MULTI-VECTOR RISK SCORING ENGINE

    * If Confirmed Not Reachable: Multiplier = 0.05 (95% Risk Reduction)
- How It Works:
  Every calculation stores all 4 inputs, mathematical weights, confidence 
  ratings, and explanation strings into the SQLite database.

5. NOTE OF "WHY" (HONEST REASONS FOR PAST SIMULATIONS & OMISSIONS)
================================================================================

Why were certain features originally simulated or omitted?

1. WHY WAS KERNEL ETW ORIGINALLY SIMULATED?
   - Windows Security Privilege Barrier:
     Accessing raw Windows Kernel ETW sessions (`Microsoft-Windows-Kernel-Process`) 
     strictly requires elevated Administrator rights (`SeDebugPrivilege`). If an 
     ordinary student or evaluator double-clicks or runs `python app.py` without 
     "Run as Administrator", native kernel ETW immediately raises `[WinError 5] 
     Access is denied` and crashes the application.
     Originally, developers simulated it via `psutil` so that the server could 
     start on standard user accounts without crashing.

2. WHY WAS THE OTP CODE RETURNED IN THE HTTP RESPONSE?
   - Local Testing & College Evaluation Convenience:
     Sending real emails requires an SMTP mail relay (like Gmail App Passwords, 
     SendGrid, or AWS SES) with verified DNS records. During development, testing, 
     or classroom grading where an SMTP server or internet mail connection is 
     not available, testers would be locked out at registration. Returning the 
     code in JSON was a development shortcut so testers could copy-paste the OTP.

3. WHY WERE SHODAN AND VIRUSTOTAL DORMANT?
   - Commercial Rate Limits & Credit Depletion:
     Free VirusTotal API keys permit only 4 requests per minute. Free Shodan keys 
     have limited monthly query credits. If a scan analyzed an SBOM with 150 
     vulnerabilities, querying Shodan and VirusTotal synchronously on every item 
     would either crash the server with HTTP 429 "Too Many Requests" errors or 
     take 40 minutes per scan. The keys were put in `.env` but never hooked up.

4. WHY WERE AI TRIAGE AND THREAT MAP PROMISED IN MARKETING?
   - Initial Project Brainstorming vs. Practical Reality:
     Early project pitch documents included modern buzzwords ("AI LLM Triage", 
     "Global Cyber Threat Map"). When development began, the engineers realized 
     that SBOM analysis operates on software packages, not Git source code or 
     network packets. The features were never built, but the marketing text 
     remained in the README.
